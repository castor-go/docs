Core API Middlewares

Configuration

Configure the server.

Castor runs with sensible defaults and no configuration at all. When you need more control, start with the defaults, override a few values with helper options, or supply the complete ServerConfig.

  • 3 scenarios
  • Go 1.27+
  • Standard library only
1

Use the defaults

Call castor.Server() without options. The server listens on all interfaces at port 3000, installs request logging, and starts with the defaults shown below.

main.go 
package main

import (
	"log"
	"net/http"

	"github.com/castor-go/castor"
)

func main() {
	api := castor.Server()

	api.Routes(
		castor.Get("/health", func(res http.ResponseWriter, req *http.Request) {
			castor.Json(res, map[string]string{"status": "ok"})
		}),
	)

	if err := api.Start(); err != nil {
		log.Fatal(err)
	}
}
Listening on http://0.0.0.0:3000

Default parameters

Default Castor server settings
Setting Default Notes
Host 0.0.0.0 Listens on all available IPv4 interfaces.
Port 3000 The HTTP port used by Start.
IdleTimeout 10s Maximum time a keep-alive connection may sit idle.
ReadTimeout 0 No read deadline; net/http waits for the request.
WriteTimeout 0 No write deadline; the handler decides when to finish.
Logger field nil Stored on the configuration; it does not install logging middleware by itself.
Request logging Enabled The Logger middleware is installed automatically and uses DefaultLogger.
Shutdown grace period 10s Internal timeout after SIGINT or SIGTERM.

A zero read or write timeout means no timeout, not an immediate failure. Set explicit limits when the server is exposed to slow or untrusted clients.

2

Override a few settings

Use the configuration helpers to change individual values while keeping the rest of the defaults. Options are applied in the order you pass them.

main.go 
package main

import (
	"log"
	"log/slog"
	"net/http"
	"os"

	"github.com/castor-go/castor"
)

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	castor.DefaultLogger = castor.RequestLogger(&castor.DefaultLogFormatter{
		Logger: logger,
	})

	api := castor.Server(
		castor.WithHost("127.0.0.1"),
		castor.WithPort(8080),
		castor.WithLogger(logger),
	)

	api.Routes(
		castor.Get("/health", func(res http.ResponseWriter, req *http.Request) {
			castor.Json(res, map[string]string{"status": "ok"})
		}),
	)

	if err := api.Start(); err != nil {
		log.Fatal(err)
	}
}
WithHost(addr)

Sets the listen address. Other defaults, including the 10s idle timeout, stay in place.

WithPort(port)

Sets the HTTP port while keeping the default host and timeouts.

WithLogger(logger)

Stores the logger on ServerConfig. Request logging is separately controlled through DefaultLogger.

The built-in request logger is the Logger middleware, which delegates to castor.DefaultLogger. Assigning DefaultLogger to a RequestLogger with your logger, as in the example, sends request logs through that logger. WithLogger keeps the logger on the server configuration.

3

Provide the full configuration

Use castor.Config with a complete ServerConfig when you need to control every HTTP setting in one place.

main.go 
package main

import (
	"log"
	"log/slog"
	"net/http"
	"os"
	"time"

	"github.com/castor-go/castor"
)

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	castor.DefaultLogger = castor.RequestLogger(&castor.DefaultLogFormatter{
		Logger: logger,
	})

	api := castor.Server(castor.Config(castor.ServerConfig{
		Host:         "127.0.0.1",
		Port:         8080,
		Logger:       logger,
		IdleTimeout:  2 * time.Minute,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 15 * time.Second,
	}))

	api.Routes(
		castor.Get("/health", func(res http.ResponseWriter, req *http.Request) {
			castor.Json(res, map[string]string{"status": "ok"})
		}),
	)

	if err := api.Start(); err != nil {
		log.Fatal(err)
	}
}

What each field controls

ServerConfig fields
Field Purpose
Host Interface passed to the TCP listener.
Port TCP port used by the listener.
Logger Logger stored on the configuration; request logging is wired through DefaultLogger.
IdleTimeout Keep-alive idle deadline. The server default is 10s, but Config replaces it.
ReadTimeout Deadline for reading the request, including the body.
WriteTimeout Deadline for writing the response.

Config replaces the entire configuration, so omitted fields become zero values. In particular, a zero IdleTimeout removes the 10-second default. Set every field you need to keep.

Mixing helpers with Config

Options are applied in order, so a helper passed after Config can override one field. For example, castor.Server(castor.Config(base), castor.WithPort(9090)) uses port 9090 because the helper runs after the full configuration.

Which approach fits?

Use no configuration for prototypes and local services. Use helpers when a few values differ from the defaults. Use Config when you need explicit read, write, and idle timeouts in one place.
