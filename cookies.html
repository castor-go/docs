Cookies

Cookie-based sessions.

Build a small fake-auth flow with cookies. The first example keeps the session on the server and stores only a token in the cookie. The second stores a signed user value directly in the cookie.

  • 2 examples
  • Go 1.27+
  • HttpOnly

Shared cookie defaults

The cookie helpers create a root-scoped, HTTP-only cookie that expires after two hours.

Default attributes applied by SetCookie and SetSignedCookie
Attribute Value
Path /
HttpOnly true; JavaScript cannot read the cookie.
MaxAge 2h
Secure Not set by the helper.
SameSite Not set by the helper.

For production traffic, also set Secure and an appropriate SameSite value. These helpers intentionally keep their defaults small; build an http.Cookie and call http.SetCookie when you need extra attributes.

1

Session token with SetCookie

This fake-auth example keeps users in an in-memory session store. The cookie carries only an opaque token, and the profile handler reads it with castor.GetCookie before looking up the user.

main.go 
package main

import (
	"log"
	"net/http"
	"strings"
	"sync"

	"github.com/castor-go/castor"
)

// Fake in-memory session store: token -> user.
var sessions sync.Map

func login(res http.ResponseWriter, req *http.Request) {
	user := castor.GetQueryParam(req, "user")
	if user == "" {
		http.Error(res, "user is required", http.StatusBadRequest)
		return
	}

	token := "session-" + strings.ToLower(user)
	sessions.Store(token, user)
	castor.SetCookie(res, "session", token)

	castor.Json(res, map[string]string{"message": "Signed in as " + user})
}

func profile(res http.ResponseWriter, req *http.Request) {
	token := castor.GetCookie(req, "session")
	if token == "" {
		http.Error(res, "not signed in", http.StatusUnauthorized)
		return
	}

	value, ok := sessions.Load(token)
	if !ok {
		http.Error(res, "session expired", http.StatusUnauthorized)
		return
	}

	castor.Json(res, map[string]string{"user": value.(string)})
}

func logout(res http.ResponseWriter, req *http.Request) {
	if token := castor.GetCookie(req, "session"); token != "" {
		sessions.Delete(token)
	}
	castor.RemoveCookie(res, "session")
	res.WriteHeader(http.StatusNoContent)
}

func main() {
	api := castor.Server().Routes(
		castor.Get("/login", login),
		castor.Get("/profile", profile),
		castor.Post("/logout", logout),
	)

	if err := api.Start(); err != nil {
		log.Fatal(err)
	}
}
Listening on http://0.0.0.0:3000

Try it

Log in to receive the cookie, then read the profile with the same cookie jar.

terminal 
curl -c cookies.txt "http://127.0.0.1:3000/login?user=Ada"
# {"message":"Signed in as Ada"}

curl -b cookies.txt http://127.0.0.1:3000/profile
# {"user":"Ada"}

curl -b cookies.txt -X POST http://127.0.0.1:3000/logout
# 204 No Content

The cookie contains only a session token; the user data stays in the server-side store. Replace the in-memory sync.Map with a shared store such as a database or Redis for real deployments, and treat this login as a fake example rather than password authentication.

2

Signed session with SetSignedCookie

This version stores the user value in the cookie itself. SetSignedCookie signs the value with HMAC-SHA256, and GetSignedCookie rejects missing, malformed, or tampered cookies.

main.go 
package main

import (
	"log"
	"net/http"

	"github.com/castor-go/castor"
)

// In production, load this from the environment or a secret manager.
const cookieSecret = "replace-this-with-a-long-random-secret"

func login(res http.ResponseWriter, req *http.Request) {
	user := castor.GetQueryParam(req, "user")
	if user == "" {
		http.Error(res, "user is required", http.StatusBadRequest)
		return
	}

	castor.SetSignedCookie(w, "session", user, cookieSecret)
	castor.Json(res, map[string]string{"message": "Signed in as " + user})
}

func profile(res http.ResponseWriter, req *http.Request) {
	user := castor.GetSignedCookie(req, "session", cookieSecret)
	if user == "" {
		http.Error(res, "not signed in", http.StatusUnauthorized)
		return
	}

	castor.Json(res, map[string]string{"user": user})
}

func logout(res http.ResponseWriter, req *http.Request) {
	castor.RemoveCookie(res, "session")
	res.WriteHeader(http.StatusNoContent)
}

func main() {
	api := castor.Server().Routes(
		castor.Get("/login", login),
		castor.Get("/profile", profile),
		castor.Post("/logout", logout),
	)

	if err := api.Start(); err != nil {
		log.Fatal(err)
	}
}
Listening on http://0.0.0.0:3000

Try it

Use a separate cookie jar and verify that a modified cookie is rejected.

terminal 
curl -c signed-cookies.txt "http://127.0.0.1:3000/login?user=Ada"
# {"message":"Signed in as Ada"}

curl -b signed-cookies.txt http://127.0.0.1:3000/profile
# {"user":"Ada"}

curl --cookie "session=tampered.value" http://127.0.0.1:3000/profile
# 401 Unauthorized

A signed cookie is readable but not modifiable: the value is signed with HMAC-SHA256, not encrypted. Keep secrets out of the cookie, use a long random signing secret from the environment, and rotate it when sessions need to be invalidated.

Which approach should I use?

Comparison of server-side sessions and signed cookies
Consideration Server-side session Signed cookie
Where state lives Server-side map, database, or cache. Inside the browser cookie.
What the cookie holds An opaque session token. A signed user value.
Logout and revocation Delete the token from the store. Remove the cookie; rotate the signing secret to revoke all sessions.
Scaling across servers Needs a shared session store. Stateless; every server needs the same secret.

Start simple, then choose deliberately.

Server-side sessions are easier to revoke. Signed cookies avoid a session store but must stay small and must never contain secrets. Both examples are fake authentication; use real password hashing and HTTPS in production.
